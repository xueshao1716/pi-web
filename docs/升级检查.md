# 升级检查清单（防误伤好功能）

> 升级/重构/大改前必读。配套：docs/能力注册表.md（能力清单）+ tests/unit/capabilities.test.mjs（契约测试）。

## 升级前（3 步）

1. **对照能力注册表查 diff**
   ```
   git diff <old>..<new> --stat | grep -E "engine/|server.mjs|public/"
   ```
   对照 `docs/能力注册表.md`——动到的文件对应哪些能力？

2. **跑全量测试（必须全绿）**
   ```
   npm test          # 148 项（142 常规 + 6 能力契约）
   ```
   任何 `cap-XX` 失败 = 好功能被破坏，禁止合并。

3. **人工抽验登记能力**（各 1 次）
   - [ ] 身份问答："你是谁" → 固定格式 + 答完即止（无 undefined、无搜索过程）
   - [ ] 复读场景：连续触发 → 同模型修正提示（不换模型）
   - [ ] 工具任务：让 AI 读文件/搜索 → 工具正常
   - [ ] 图片消息：带图 → vision 模型识别
   - [ ] 模型切换：选 ox-alpha → 实际用 ox（自报正确）

## 升级中（纪律）

- **删除/弱化登记能力** → 契约测试证明 + 注册表记录原因，缺一不可
- **新模块命名** → 先 `ls engine/` 查重（model-probe 撞名教训：通断探测差点覆盖能力探测）
- **模板拼接** → 变量必须 `|| "默认"` fallback，防 undefined 泄漏（undefined 清理能力不背锅）
- **模型 id** → 含 `/` 的（openrouter/stealth/ox-alpha）用 `indexOf+slice` 拆，禁止 `split("/")` 截断

## 升级后（回归）

- [ ] 全量测试再跑一遍（确认无 flaky）
- [ ] 看板：版本号递增 + 前端 `?v=` 递增（防缓存）
- [ ] 记忆日志记录：本次升级动了哪些能力、验证结果
