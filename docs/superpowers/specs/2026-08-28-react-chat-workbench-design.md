# React 聊天工作台设计规格

日期：2026-08-28
状态：首轮实施基线

## 背景

`D:\pi-web\frontend` 是 pi-web 当前主线前端。`public/` vanilla 版本保留，不作为本轮视觉改造对象。React 版本已有聊天、会话、模型、资产、任务、工作空间、终端和移动端布局，但视觉层级、动态状态和跨尺寸一致性仍需要收口。

本轮目标不是重写后端或替换路由，而是让最常用的聊天工作台成为一个稳定的产品基座：用户能快速找到会话，能清楚理解小语是否正在执行、正在调用什么工具、是否需要确认，并能在手机上完成同样的核心操作。

## 设计方向

- 深色专业 AI 工作台，信息密度适中，优先服务重复操作。
- 保留主色和少量背景光感作为空间层次；不让大面积玻璃、渐变或装饰抢走内容注意力。
- 对话内容采用清晰的阅读列；工具调用、思考、附件和错误属于可折叠的辅助层。
- 交互状态必须靠结构、文案、图标和语义色共同表达，不依赖颜色单独传达。
- 桌面端优先三栏效率，移动端优先单手操作和稳定底部输入区。
- 所有触屏操作保持至少约 40px 命中区；固定格式控件使用稳定尺寸，避免动态内容导致布局跳动。

## 首轮范围

只改造以下聊天主路径组件：

- `src/AppLayout.tsx`：桌面 rail、会话栏、主区、右侧面板和移动抽屉的层级与边界。
- `src/components/Sidebar.tsx`：品牌头、新建、搜索、会话分组、选中态和移动端操作命中区。
- `src/components/ChatArea.tsx`：顶栏状态、欢迎空态、消息区、加载态、确认层和输入区外壳。
- `src/components/Message.tsx`：用户消息、助手消息、思考和工具卡的阅读层级。
- `src/components/SendBox.tsx`：文本输入、命令/文件引用、附件、语音、模型选择、发送/停止状态。

首轮不改变 API 契约、消息树结构、SSE 事件名称、会话持久化、模型路由和 vanilla 入口。

## 交互验收

### 空态与加载

- 无当前会话时，欢迎页只保留一个明确的第一动作，并提供终端、模型中心和命令面板等次级入口。
- 会话消息加载时使用与消息布局一致的骨架，不出现空白跳变或超出消息列宽的骨架条。
- 没有会话、会话列表为空、搜索无结果分别给出明确空态。

### 流式、停止与错误

- 流式开始后，顶栏状态明确显示执行中，输入区变为停止操作，发送按钮不可重复提交。
- 增量文本、思考、工具调用和工具输出在同一轮内保持稳定顺序；内容增长不会把输入区推出视口。
- 用户手动停止后，已产生的内容和工具状态保留，运行中的工具显示已停止，不伪装成成功。
- SSE 错误后，错误信息与已产生内容同轮保留，并提供下一步动作；90 秒无事件提示不遮挡消息和输入区。
- 后台其他会话执行时，状态显示“后台执行中”，但不能误把当前会话显示成正在流式。

### 工具和危险操作

- 工具卡至少区分运行中、已完成、已停止、失败四种状态；输出默认折叠，点击后可查看。
- 危险操作确认层不能遮住仍需阅读的上下文；允许和拒绝按钮在桌面/手机均可触达，默认焦点和 Escape 行为可用。

### 输入区

- Enter 发送、Shift+Enter 换行；斜杠命令和 `@` 文件搜索可用键盘上下选择并回车确认。
- 上传文件、语音录入、模型参数、切换模型和停止生成都有明确忙碌态，失败不能静默吞掉用户需要知道的错误。
- `input type=time/date/color/range/select` 统一可读的主题样式；隐藏文件输入只作为选择器，不作为视觉控件。

## 响应式验收尺寸

- 手机窄屏：375 x 812，检查底部 TabBar、FAB、输入区、抽屉和确认层无重叠。
- 手机横向/小平板：768 x 900，检查侧栏抽屉、消息列宽和右栏切换。
- 桌面：1440 x 900，检查 rail、会话栏、消息阅读列和右侧工作区边界。

每次首轮改动至少保留一张桌面和一张手机截图；动态行为用真实交互验证，不能只凭静态截图判定。

## 原生控件清单

首轮逐项处理或记录理由：

- 文本、密码、搜索、数字输入：`input-pi` 统一背景、边框、聚焦环和占位符。
- `textarea`：统一最小高度、扩展/滚动规则和禁用态。
- `select`：统一颜色、箭头区域和深浅主题下的选项可读性。
- `input[type=time/date]`：统一控件背景和系统图标对比度，手机上保持可点击宽度。
- `input[type=color]`：保留原生取色能力，但包在主题化控件容器内。
- `input[type=range]`：统一轨道、滑块和焦点态。
- `input[type=file]`：保持隐藏，仅通过带图标的可见按钮触发。
- `audio`：确保控制条在深色和浅色主题中可见，窄屏不溢出。

## 工程约束

- 不清理或覆盖当前工作树中的用户未提交改动。
- 不把 React 构建产物写入 `public/`；`frontend/dist` 的既有变更单独保留，不作为本轮手工清理对象。
- 优先复用现有 token、Radix、Lucide、SWR 和 API 封装；不新增组件库。
- 每一轮改动后执行类型检查、设计契约、主题契约和对应的真实页面回归。
- Sonnet 5 只做分块评审：一次只提供一个页面或一个状态切片，避免大请求造成中转拒绝；评审结论必须回到本地截图、DOM 和测试证据上。
