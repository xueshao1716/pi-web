# pi-web 全局 UI 系统精修设计

**日期：** 2026-08-31  
**状态：** 已批准，进入实施

## 目标

在不改变 pi-web 产品身份、功能边界和聊天主流程的前提下，把 React 工作台从“功能拼装完成”提升为统一、成熟、耐看的个人 AI 工作台。整体保留深色专业工具感；问题严重的功能页允许明显重排，但不做品牌重塑。

## 设计判断

当前主要问题不是配色不足，而是页面组织和组件消费设计系统的程度不一致：基础 token、三栏底色和主要控件已有统一方向，但模型、主题、系统、应用、任务、会话库等页面出现信息同权、卡片滥用、过多小字、空状态不统一和移动端重复导航。

因此本轮采用“保留视觉世界，重做页面层级”的路线，而不是换一套颜色或堆更多渐变。

## 视觉方向

- 模式：Operate，服务高频工作而非营销展示。
- 气质：深色、安静、精密、有温度的专业工作台。
- 主色：继续使用当前 indigo accent；状态色只表达状态，不装饰页面。
- 表面：以明度、间距和细边框区分层级，常驻页面不滥用玻璃、光晕和渐变。
- 字体：保留现有中英文字体栈，不引入网络字体；正文不小于 13px，说明文字以 12px 为主，11px 仅用于 ID、时间和测量值，10px 只用于 badge。
- 图标：统一 Lucide，禁止用 emoji 作为结构图标。
- 动效：只保留短促的状态反馈、页面进入和面板切换；尊重 reduced-motion。

## 全局页面结构

非聊天页面统一为：

1. 页面标题区：中文主标题、简短说明、可选右侧主操作；取消重复的英文 eyebrow。
2. 状态摘要：只在用户进入页面就需要判断状态时出现，不默认套“三张大数字卡”。
3. 主要任务区：第一屏优先展示当前最常用的操作。
4. 次要配置或技术细节：使用折叠、二级分段或页面底部的“高级”区。

统一使用 4/8px 间距体系。页面横向 gutter 为手机 16px、桌面 24px；主要区块间距 24–32px；卡片内部 12–16px。

## 页面设计

### 模型中心

第一屏只回答三个问题：当前在用什么、如何找到合适模型、如何切换。

- 顶部加入当前模型焦点区，显示当前模型、Auto 路由说明和关键状态。
- 搜索、类型、能力、免费优先合并为一个清晰工具栏。
- 模型从“每张卡都像详情页”压缩为可比较的紧凑卡：名称、provider、免费/推理/视觉、上下文和主操作。
- 服务商通道、累计用量和 provider 明细下沉为“通道与用量”折叠区。
- 清除固定 emerald/purple/sky Tailwind 色，改用语义 token。

### 主题系统

面向普通用户的外观设置与开发者 token 工具分层。

- 对齐统一页面标题。
- 主题画廊成为主区域；当前主题与实时预览在桌面形成主辅布局，手机自然单列。
- 主色、层级密度、壁纸集中到“精调”面板。
- Token 速览和 CSS 导出进入默认收起的“开发者选项”。
- 删除 9px 文本和不受控 transition-all。

### 系统

第一屏从“能力宣传”改为“当前状态”。

- 顶部展示服务状态、版本、运行时长和网络入口。
- 更新检测与网络配置是两个主任务区。
- 系统能力移到页面末端并默认折叠。
- 正常、警告、失败全部使用语义 token，状态不仅依赖颜色。

### 应用中心

- 顶部不再使用五项同权横向胶囊。
- 桌面采用左侧工具导航 + 右侧工作区；手机采用可换行的紧凑工具选择器。
- 工具按“知识资产”和“系统改进”分组。
- 每个工具有自己的标题、说明和主操作语境。

### 任务中心与会话库

- 统一 PageHeader、EmptyState、状态 badge 和加载状态。
- 任务空状态使用 Lucide 图标并提供“创建第一个任务”动作。
- 会话库桌面保留表格；手机改为卡片行，不强迫横向滚动完成常用操作。
- 运行历史、ID、时间等元数据统一为 11px；正文保持 13px。

### 聊天与消息

聊天结构不重做，只清理主题适配：

- 用户、助理、推理、信息、成功、失败使用语义 token。
- 移除固定 purple/sky/red/emerald 和装饰性渐变。
- 保留工具卡、持久化 Run、断线恢复和输入框行为，不改数据流。

## 全局导航

### 桌面

- Rail 与会话栏保持现状。
- “工作空间/交付物/终端/活动/TUI”恢复为真正的右侧上下文面板，宽屏不再默认覆盖全屏。
- 终端和 TUI可提供展开能力，但展开是显式动作，不让所有工具共用全屏覆盖。
- 右面板有明确标题、图标和关闭按钮。

### 移动端

- 底部 TabBar 保留五项：对话、会话、资产、任务、更多。
- 删除可拖动 FAB，避免与 TabBar 重复、遮挡内容和产生拖拽/点击冲突。
- “更多”打开统一功能面板，承载灵犀、专项、模型、应用、引擎、主题、会话库、系统及辅助工具入口。
- 设置类子页保持“更多”活跃状态。
- 固定导航尊重安全区，触控目标不小于 44px。

## 公共组件

新增小而专一的展示组件，不新造大文件：

- `PageHeader`：统一标题、说明、可选操作和状态。
- `SectionHeader`：统一区块标题与辅助动作。
- `StatusTile`：用于有真实状态判断价值的小型摘要，不作为默认页面模板。
- `MoreMenu`：移动端统一功能入口，替代 `MobileFab`。

现有 `EmptyState` 收口：只使用 Lucide 图标、标题、说明和可选 CTA；不再提供 emoji 结构入口。

## 响应式与无障碍

- 验证 375×812、390×844、768×1024、1440×900。
- 页面不能产生非必要横向滚动；宽表格在手机用卡片替代。
- 交互元素有可见 focus，图标按钮有 aria-label，选中/展开状态使用 aria-pressed 或 aria-expanded。
- 表单保留可见标签或可访问名称，错误信息就近展示且保留输入。
- reduced-motion 下取消非必要位移和入场动画。

## 不做

- 不改后端 API、模型路由、持久化 Run、会话数据结构。
- 不新增产品功能。
- 不重做聊天核心交互。
- 不引入大型 UI 框架或新运行时依赖。
- 不触碰主工作区 refine/workshop/图片工作台的未提交改动。

## 验收

- `npm test` 全绿。
- `npx tsc --noEmit -p frontend` 全绿。
- `frontend/tests/design-contract.test.mjs` 全绿；若基线存量失败与本轮范围重叠，应在本轮修复。
- `npm run build` 成功。
- Impeccable detector 对改动目标无未解释的新增问题。
- 桌面和手机四个视口截图检查：导航无重复、无溢出、信息层级清晰、页面属于同一产品。
