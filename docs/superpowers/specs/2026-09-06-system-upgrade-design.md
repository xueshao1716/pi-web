# 元枢系统升级设计：主驾工作台与能力中枢

## 目标

把现有“能力很多但入口分散”的 pi-web，升级成一个以自建元枢引擎为主线的个人智能工作台：用户能看懂系统正在做什么、为什么这么做、产物在哪里、下一步能继续什么；开发者能定位模型、工具、记忆、情绪和任务链路的问题。

## 升级原则

1. 不推倒现有能力，优先收拢入口和状态。
2. 主驾（元枢）负责判断、编排、记忆和复盘；pi/dsh/媒体/工作坊作为可观测的执行通道。
3. 每个页面都要有明确的“现在状态 / 下一步动作 / 异常恢复”三件事。
4. UI 统一为“工作台 + 能力舱”结构：主内容优先，配置和诊断后置。
5. 先做高收益的公共骨架和观测能力，再扩展新功能。

## 一、整体产品结构

### 1. 主工作台（Board）

Board 变成登录后的系统总览：

- 顶部显示当前主驾、健康状态、情绪状态、正在运行的任务。
- 中部提供四个高频入口：继续对话、开始创作、查看交付、处理待办。
- 下部展示最近会话、最近产物、任务队列和引擎事件流。
- 所有卡片都能跳到对应详情，不复制业务逻辑。

### 2. 对话工作台（Chat）

- 保留现有聊天能力，但增强“任务阶段条”：判断 → 执行 → 汇总 → 交付。
- 工具调用、模型切换、情绪镜像、记忆命中统一收进可展开的运行面板。
- 交付物在正文后形成稳定的资产卡，支持继续编辑、打开所在目录、再次运行。
- 空状态改为可执行入口，而不是静态欢迎文案。

### 3. 能力中心

将模型中心、引擎页、系统页、应用页统一成“能力中心”，保留独立路由但共享页头和状态卡：

- 模型：可用通道、健康、延迟、最近失败、当前选择。
- 引擎：主驾/次席、插件、工具、循环策略、评测分数。
- 系统：服务、端口、工作空间、版本、网络入口。
- 应用：已挂载能力和可执行入口。

## 二、自建引擎升级

### 1. 主驾运行上下文

新增统一的运行快照接口，返回：runId、阶段、主驾、模型、工具调用、记忆命中、情绪变化、产物和错误。Chat、Board、Engine 共用该快照，不再各自轮询不同数据源。

### 2. 工具循环可观测

把 unified-chat / yuanshu-loop 的关键事件标准化为：`turn_started`、`reasoning`、`tool_started`、`tool_finished`、`handoff`、`memory_written`、`artifact_created`、`turn_finished`、`turn_failed`。前端按事件渲染阶段条，后端保留最近运行摘要。

### 3. 记忆与情绪闭环

- 记忆：继续沿用 current/superseded 事实模型，增加“本轮命中 / 本轮写入 / 被替代”摘要。
- 情绪：把 VAD 结果转成轻量状态，不抢正文注意力；异常情绪只显示行动建议。
- 复盘：任务完成后写入可回看的经验摘要，而不是只留下日志。

### 4. 引擎管理页

Engine 页从“配置列表”升级为“引擎控制台”：主驾切换、能力矩阵、健康探活、评测趋势、最近失败原因和一键诊断都在同一页。

## 三、UI 方向

推荐采用“静谧的操作台”视觉：

- 浅色晨雾底 + 墨色文字 + 单一青蓝主色，避免全站多彩竞争。
- 页面采用大标题、短描述、状态徽标、宽松卡片间距。
- 运行态使用细线、脉冲和阶段轨迹，避免大面积动画。
- 桌面端三层结构：左侧导航 / 中央工作区 / 右侧运行舱；移动端折叠为底栏 + 抽屉。
- 公共组件统一：PageHeader、StatusTile、SectionHeader、EmptyState、ErrorState、RunTimeline。

## 四、功能板块处理顺序

1. Board + AppLayout：统一入口、状态摘要和导航。
2. ChatArea + Message + SendBox：运行阶段、交付卡和异常态。
3. Engine + 引擎 API：主驾控制台和运行快照。
4. Assets + Tasks + SessionDb：统一筛选、详情和继续动作。
5. Workshop + ModelHub + System：统一页头、状态和配置体验。
6. 移动端适配、主题细节、空/错/加载状态收尾。

## 五、后端接口与模块边界

- 新增 `run-observability.mjs`，只负责运行事件规范化和快照读取。
- `unified-chat.mjs`、`run-manager.mjs`、`yuanshu-loop.mjs` 只发布事件，不直接关心 UI。
- `server.mjs` 只挂载路由和组合依赖，不新增业务解析。
- 前端 `api.ts` 增加 `RunApi`，页面通过 SWR 读取快照。
- 所有新增行为先以单测覆盖，再做前端契约测试。

## 六、验证标准

- 全量 Node 单测保持全绿。
- 前端 `tsc --noEmit` 和生产构建通过。
- 主工作台、聊天、引擎、资产、任务在桌面和移动宽度下无明显布局回退。
- 新增运行事件在任务成功、失败、取消、断线恢复四种路径可观测。
- 旧 API 和旧路由保持兼容。

## 实施方式

第一批只做公共骨架、Board、运行快照和 Engine 控制台；第二批改造 Chat 与资产交付；第三批统一其余页面和移动端。每批独立提交、独立验证，可随时回退。
