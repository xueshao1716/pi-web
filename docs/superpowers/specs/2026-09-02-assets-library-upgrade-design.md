# 资产库升级设计

日期：2026-09-02
状态：已获方向确认，待伙伴审阅细节

## 1. 目标与边界

将当前“生成物网格 + 交付物列表”升级为媒体优先的统一资产库：用户可以快速找到资产、判断内容、在当前页面预览，并完成常用管理动作。首屏优先图片/视频/音频等媒体，不把页面做成传统文件管理器。

本阶段不做外部视频聚合源、标签系统、云同步、智能分类或复杂权限系统。沿用现有工作空间根目录与后端安全文件服务，不改变已有 provider、会话和生成流程。

## 2. 信息架构

页面分为三个连续层次：

1. **资产总览条**：显示资产总数、媒体数量、交付数量和当前筛选结果；提供搜索、类型筛选、排序和视图切换。
2. **统一资产区**：生成物与交付文件以统一条目呈现。媒体使用缩略图网格，非媒体使用紧凑列表/文件卡片。交付物保留来源标记，目录作为可进入的文件条目处理。
3. **详情/预览层**：桌面端使用右侧详情面板，移动端使用全屏底部抽屉。预览和元信息共用同一个选中资产状态，避免图片灯箱与交付列表两套交互。

默认排序为最近更新；筛选支持全部、图片、视频、音频、文档/其他，并保留来源筛选（生成物/交付）。搜索匹配文件名和相对路径。结果为空时，说明当前条件并提供清除筛选动作。

## 3. 预览与操作

- 图片：大图预览、缩放适配、失败占位、打开原文件、下载。
- 视频：页面内 `<video controls preload="metadata">` 播放，支持 MP4/WebM，显示加载失败状态；使用后端 Range 服务以支持拖动进度。
- 音频：页面内音频控件，展示文件名和时长可用时的基本信息。
- 文本/Markdown/JSON：详情面板内读取并展示可滚动文本；超出范围或读取失败时明确提示。
- 其他文件：显示类型图标、大小、路径与“新窗口打开/下载”。
- 管理：重命名、删除；删除必须有明确确认，并在成功后刷新列表、关闭已失效预览。
- 批量：选择多个文件后显示固定操作栏，支持批量下载（若后端暂无批量接口，第一阶段先提供逐项下载并明确反馈）和批量删除确认。

所有文件操作使用现有签名 URL/鉴权 URL 体系，前端不拼接未校验的本地路径；删除和重命名继续走后端工作空间安全检查。

## 4. 视觉与响应式方向

继承 pi-web 现有视觉系统，不引入新主题、渐变或玻璃拟态。资产库采用“安静的工作室画廊”方向：大而清楚的媒体缩略图、克制的元信息、明确的选中态，减少无意义装饰。

桌面端以约 5–6 列媒体网格为主，详情面板打开后网格自然收缩而非被遮挡；非媒体文件采用统一的文件卡片。移动端改为 2 列缩略图，工具栏允许横向滚动，选中后用底部操作栏承载动作；预览层覆盖安全区域并提供明显关闭按钮。

交互状态必须完整：加载骨架/加载提示、图片加载失败、视频不可播放、空结果、删除中、删除失败、重命名冲突、批量操作结果、键盘 Escape 关闭预览。遵守 reduced motion，不依赖悬浮才能发现关键操作。

## 5. 数据与组件边界

前端增加统一的资产视图模型，将现有 `Artifact` 与交付条目映射为可预览条目；不改变现有生成接口。建议拆分为：

- `AssetToolbar`：搜索、筛选、排序、视图切换与统计；
- `AssetGrid` / `AssetList`：统一渲染和选择状态；
- `AssetCard`：缩略图、类型、来源和选中态；
- `AssetPreview`：图片、视频、音频、文本和通用文件预览；
- `AssetDetails`：元信息及操作；
- `Assets.tsx`：数据拉取、筛选、选择、刷新和路由级状态协调。

第一阶段尽量复用现有 `WsApi.artifacts()`、`WsApi.deliveries()`、`withFileToken()` 和后端 `/api/ws/file`。只有当统一列表或批量操作确实需要时才扩展 API，避免为视觉升级重做工作空间协议。

## 6. 验证标准

实现前先补充前端结构契约，覆盖：统一条目映射、媒体类型识别、预览路由、筛选/排序、失效选中项清理、删除确认和移动端操作栏。

实现后至少验证：

- 单元测试与全量 `npm test`；
- `frontend npx tsc --noEmit`；
- `frontend npm run build`；
- `node --check` 涉及的后端文件（如有修改）；
- `git diff --check`；
- Impeccable detector 对修改的页面和样式运行一次；
- 真实服务中检查资产列表、图片加载、视频 Range 响应、鉴权下载和删除/重命名失败边界；
- 375px 左右移动视口与桌面视口的无横向溢出检查。

完成标准不是“页面看起来更漂亮”，而是：用户无需离开资产库即可判断并使用主要媒体资产；文件管理操作有明确反馈；空、错、加载和移动端状态不塌；原有生成物和交付物仍可访问。
