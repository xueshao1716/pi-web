# 元枢统一工作说明层

用户已确认方案 C，并授权连续推进。先建立统一解释对象和聊天入口，再接入工作台、引擎和验收，使用现有主题与组件，不增加独立导航。

## 用户可见行为

每轮显示目标、现在的状态、执行者及模型、已记录的选择依据、工具与子智能体、记忆写入、产物、验证、问题和下一步。默认摘要保持简短，展开显示分组记录和时间。手机单列、按钮至少 44px、长文本换行。说明不会在结束八秒后消失，也不会把其他会话的记录带过来。

聊天以当前会话最近一轮为准；工作台显示当前与近期工作；引擎诊断使用同一份说明；验收页独立显示运行证据，不能拿其他任务的验证证明当前 Git 工作区通过。

## 数据与边界

新增纯函数聚合运行元数据、运行事件和匹配 runId/sessionId 的 AIBody 记录，输出版本化 WorkExplanation。通过现有运行 API 返回，不新增生成式调用，不更改引擎循环，不执行新任务。概览支持按会话过滤，避免全局最近八条挤掉该会话记录。摘要与详情采用同一数据来源。

事件只提取白名单字段，文本脱敏并限长。不展示系统提示词、模型历史、隐藏推理、工具参数或整段工具输出；子智能体任务和返回结论以限长、脱敏的摘要展示。“依据”仅表达已记录的路由理由、用户选择和承接关系，不推测模型隐含思维。

工具开始与结束按调用 ID 合并，子智能体按子运行 ID 合并。结束状态和执行证据分开：结束只说明本轮结束，检查通过只说明已执行的检查通过，不等于全局验收或人工认可。模型自报、运行时检查通过、检查失败、无验证记录分别标注。记忆写入不称为命中；产物事件不自动代表存在、可播放或已交付。

本轮只接入既有记录，不增加自动验收执行器。现有聊天执行链路尚未发送独立的运行时检查事件，因此这些运行显示“尚无检查记录”；工具执行成功或模型回复“已检查”都不能替代该证据。运行时检查的真实采集属于后续接入工作。

## 空缺、异常与兼容

旧记录按可用字段解释，不补造历史；没有子智能体事件不等于能力不可用。接口读取失败明确提示并保留上次数据。解释层失败不影响任务执行。失败类型提供可操作的排查方向；只有实际可恢复的任务才显示原有继续入口。

## 验收

核心逻辑先失败测试再实现，覆盖完成但未验证、真实验证失败/通过、自报、去重、隐私、会话隔离、历史缺失及排序。执行类型检查、全量测试、构建和前端检测；浏览器确认四页及手机宽度。后端部署前检查活动运行，重启后核对健康接口和实际页面资源。提交并同步既有两个远端，不发送未经授权的外部通知。
