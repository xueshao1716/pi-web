# 聊天下载与连续创作可用性修复

沿用用户已经授权的 AI 主导、人类辅助方向，在现有界面完成修复；不再增加确认流程。

## 设计与验收

- 下载：本机文件链接按当前服务地址与当前登录恢复访问，清除历史签名；外部地址不附带本系统令牌。视频按钮展示准备、保存、成功/失败及原文件入口。保留安卓真实系统保存流程。
- 连续创作：主体承载一句话构思、输出类型、AI 草稿、生成与结果；时间线和设定作为辅助。采用草稿一次保存完整角色外貌、服装、风格及当前段落，已有详细字段不被表单丢弃。
- 下一段承接前文的实际正文及设定，预览仅检查输入，不伪造排队记录。不把上一镜头结果当作新镜头产出。图像/视频未接入真实参考输入时明确说明文字连续性的限制。

## 实施

- [x] `frontend/src/lib/file-access.ts`：用本机、跨端旧域名、过期签名、外部 CDN 用例验证文件地址和令牌隔离；`api.ts` 接入，`Message.tsx` 展示可重试的下载状态。
- [x] `frontend/src/lib/story-draft.ts`：测试 AI 草稿完整保存、切换项目无串写、已有字段保留；小组件拆分构思入口、设定、结果，调整 `StoryWorkbench.tsx` 主流程。
- [x] `engine/story-store.mjs` 与 `story-orchestrator.mjs`：测试继承实际正文、预览无持久化副作用、异常不留运行中状态；按失败用例修复。
- [x] 浏览器临时造数走完整流程和下载；同时检查桌面与手机宽度。运行全量测试、类型检查、构建、Impeccable。发布动作由本轮提交和在线复核记录确认。

浏览器只对临时测试数据写入；真实会话用于只读下载验证，不发消息、不改用户作品。

## 本轮验证记录

- 全量 847 项测试通过，TypeScript、构建、设计检测通过。
- 真实历史会话点击下载得到 4,480,227 字节视频；原生安卓保存协议的既有字节传输测试通过，未连接实体手机验收。
- 浏览器桌面 1440px / 手机 390px：使用临时故事存储及确定性模型适配器，验证建项、完整草稿保存、只读预览、生成、错误重试、续写前文、结果归属和类型切换；无页面错误或横向溢出。
- 本轮没有重新调用外部视频模型评估出片质量，画面一致性和自动长片拼接的限制已明确展示。
